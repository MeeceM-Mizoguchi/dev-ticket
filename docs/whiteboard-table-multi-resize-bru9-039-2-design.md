# BRU9-039-2 ホワイトボードの表: 複数行・複数列の一括サイズ調整 — 設計書

> 分類: 機能改善 / **実装済み**（本書は実装後の内容に更新済み）。
> 要件: 「複数の行や複数の列を選択して、幅・高さを同時に調整できる機能」

---

## 0. 対象と現状

対象はホワイトボードの表（BRU5-042）。関係するファイルは 3 つ。

| ファイル | 役割 |
|---|---|
| `src/app/lib/whiteboardTable.ts` | 表のデータモデル、行・列の追加/削除、再レイアウト（`reflowTables`） |
| `src/app/components/whiteboard/TableResizeOverlay.tsx` | 列/行の境界つまみ・四隅つまみ（手動リサイズ） |
| `src/app/components/whiteboard/TableRowColControls.tsx` | 行・列の追加/削除パネル |

### データモデル（既存）

- セル = 標準の `rectangle` ＋ バインドテキスト。`customData.wbTable = { tid, r, c, cw?, rh? }`。
- `cw` / `rh` は **列・行に属する全セルへ同じ値を書き込む**（＝実質「列幅」「行高」の手動値）。
- `reflowTables` が `onChange` のたびに全表を再計測し、隙間なくタイルし直す。原点は左上セル `(0,0)`。

### 再レイアウト規則（既存・本設計の前提）

```
列幅 colW[c] = cw があれば cw（内容より狭ければテキストを折り返す）… 手動が“上書き”
             なければ 内容の自然幅（最小 MIN_COL_W = 40）
行高 rowH[r] = max(MIN_ROW_H = 32, 内容の必要高, rh)               … 手動は“下限”としてのみ効く
```

> ⚠ **幅と高さで手動値の意味が非対称**。列幅は手動値が勝つ（内容より狭くできる）が、行高は下限なので
> 内容が必要とする高さより低くはできない。本機能の「高さをそろえる」仕様（§3.4）はここに従う。

### 現状できるサイズ調整

| 操作 | 効果 |
|---|---|
| 列境界をドラッグ | **その 1 列だけ** `cw` を書き換え |
| 行境界をドラッグ | **その 1 行だけ** `rh` を書き換え |
| 境界をダブルクリック | その 1 列/行を自動フィットへ戻す（`cw`/`rh` を削除） |
| 四隅をドラッグ | 表全体を比率でスケール（全列・全行に手動値を焼き込む） |

---

## 1. 課題

1. **1 本ずつしか変えられない。** n 列を同じ幅にするには n 回ドラッグが必要で、しかも目分量なので揃わない。
2. **そもそも「列を選ぶ」手段がない。** セルは `groupIds` で束ねてあるため 1 クリックでは表全体が選択される。
   個別セルを選ぶにはグループへ入ってから Shift+クリックを行数ぶん繰り返すしかなく、10 行の表で 1 列を
   選ぶのに 10 クリックかかる。
   → **要件の「複数の列を選択して」を成立させるには、まず “列/行を選ぶ UI” が要る。** ここが本チケットの本体。
3. **高さは仕様上そろわない場合がある**（`rh` が下限のみのため）。UI 側で誤解を生まない見せ方が必要。

---

## 2. 設計方針（3 本柱）

| # | 柱 | 内容 |
|---|---|---|
| **A** | **行/列ヘッダー帯** | 表の上端・左端に Excel 風のヘッダー帯を重ね、クリック/ドラッグ/Shift で列・行を丸ごと選択できるようにする |
| **B** | **選択への一括リサイズ** | 選択中の列/行のいずれかの境界をドラッグすると、**選択中の全列/全行が同じサイズになる**（Excel/Word と同じ挙動） |
| **C** | **一括の自動フィット・そろえる** | 境界ダブルクリックで選択全体を自動フィットへ復帰。パネルに「幅をそろえる／高さをそろえる／自動」を追加 |

副次効果として、既存の**行・列の追加/削除パネルも一気に使いやすくなる**（「3 列選択 → 右に 3 列追加」が
ヘッダー帯のドラッグ 1 回でできる）。

## 3. UI 仕様

### 3.1 行/列ヘッダー帯（新規・柱 A）

- **表示条件**: `canEdit` かつ表が選択されている間（既存つまみと同じ `selectedTableId(api) != null`）。
- **位置**: 表の上端の外側／左端の外側に **画面 16px 固定**の帯（ズームしても太さは一定＝既存 `GRIP` と同じ思想）。
  帯は列幅・行高に合わせて区画に分かれる。
- **見た目**: 既定 `#f1f3f5` ＋ `1px` 罫線。ホバーで淡いグレー。**選択中の区画は ACCENT `#6965db` の 20% 塗り**。
- **操作**:

| 操作 | 効果 |
|---|---|
| 区画をクリック | その列（行）を単独選択（＝その列の全セルを `selectedElementIds` に設定） |
| 帯の上をドラッグ | 通過した範囲を連続選択 |
| Shift+クリック | 直前のアンカーからの範囲選択 |
| Ctrl/⌘+クリック | その列（行）を選択にトグル追加 |
| 帯の区画の境目 ±4px | **リサイズとして扱う**（`bandEdgeTarget`。カーソルも `col-resize`/`row-resize` に変わる） |
| 帯の境目のダブルクリック | その列/行（選択中なら全部）を自動フィットへ |

- 帯の「中身」のダブルクリックには何も割り当てない（境界ダブルクリック＝自動フィットと衝突させない）。
- **z 順**: 列/行つまみ → コーナー → 帯。帯は表の外側にしか無いので、表の内側の既存つまみ（コーナー含む）は
  一切影響を受けない。四隅の外側だけ帯が勝つが、Excalidraw の四隅ハンドルは表の角そのものにあるため
  四隅リサイズは従来どおり掴める。帯の中の境目リサイズは z 順で解決せず、帯自身の当たり判定
  （`bandEdgeTarget`）で処理する。

### 3.2 一括リサイズ（柱 B）

**対象の決め方**（`resolveSizeTargets`）— 曖昧さを残さないため優先順で判定する:

1. **明示の軸選択がある**（ヘッダー帯で選んだ）かつ種別が一致し、ドラッグした index がその中にある → **その全 index**
2. 軸選択が無い場合の**補助ルール**（手でセルを複数選択した人向け）:
   - 列: 選択セルが「**全行そろった列**」を 2 列以上含み、ドラッグした列がその 1 つ → その列集合
   - 行: 選択セルが「**全列そろった行**」を 2 行以上含み、ドラッグした行がその 1 つ → その行集合
   - ※ **表全体選択（1 クリックのグループ選択）は対象外**。従来どおり単一列/単一行だけが変わる（既存挙動の互換）
3. どれにも当たらない → `[index]`（＝現状どおり）

**適用値**: Excel/Word と同じく **選択中の全列を「同じ幅」に揃える**（差分適用ではなく統一）。

**ドラッグ追従の式**（重要）: 対象のうち「ドラッグした境界より左（上）にある個数」を `k` とすると、対象を
すべて幅 `w` にしたとき境界は `k·w` ぶん動く。素直に `w = startSize + dx` にすると境界がカーソルの `k` 倍の
速さで走ってしまうため、

```
w = max(MIN_COL_W, round(startSize + dx / k))     // 行は MIN_ROW_H と dy
k = 対象 index のうち「ドラッグした index 以下」の個数
```

とし、**ドラッグした境界がカーソルに一致して追従する**ようにする。

**フィードバック**: 対象になる列/行はヘッダー帯の区画をハイライトし、ドラッグ中は対象列（行）の全体に
ACCENT 10% の薄い塗りを重ねて「どこが一緒に変わるか」を明示する。

### 3.3 一括の自動フィット（柱 C-1）

境界のダブルクリックは §3.2 と同じ `resolveSizeTargets` を使い、**対象すべての `cw`/`rh` を削除**して内容
フィットへ戻す（現状は 1 本だけ）。

### 3.4 パネル拡張（柱 C-2）

`TableRowColControls` に「サイズ」セクションを追加する。**2 列以上／2 行以上が対象のときだけ**表示。

```
列   [左に追加][右に追加][削除]
     [幅をそろえる][自動幅]        ← 追加
行   [上に追加][下に追加][削除]
     [高さをそろえる][自動高さ]    ← 追加
```

| ボタン | 動作 | 理由 |
|---|---|---|
| 幅をそろえる | `round(選択列の現在幅の合計 / 列数)` を全選択列の `cw` に | **表の総幅を変えずに**均等割り（Word の「幅を揃える」と同じ） |
| 高さをそろえる | `max(選択行の現在高)` を全選択行の `rh` に | `rh` は下限としてしか効かない（§0）ため、**最大値に合わせないと実際には揃わない**。平均を入れると「揃えたのに揃わない」になる |
| 自動幅／自動高さ | 選択列/行の `cw`/`rh` を削除 | 内容フィットへ復帰。境界ダブルクリックのパネル版 |

## 4. 実装設計

### 4.1 `whiteboardTable.ts`（中核・追加が集中する）

**明示の軸選択をモジュールレベルの状態として持つ。** `whiteboardText.ts` の編集中テキスト状態と同じ流儀で、
オーバーレイとパネルの両方から参照する（React の props バケツリレーを増やさない）。

```ts
export type TableAxisSel = { tid: string; kind: "col" | "row"; indices: number[] } | null;

// ヘッダー帯の操作でのみセットされるローカル UI 状態（Yjs へは同期しない）
export function setTableAxisSel(sel: TableAxisSel): void;

// 妥当性を検証して返す。壊れていれば内部でクリアして null。
//   ・tid の表が存在しない / indices が R,C の範囲外（行列の増減で崩れた）
//   ・現在の selectedElementIds が「その軸のセル集合」と一致しない（別の選択に切り替わった）
export function tableAxisSel(api: any): TableAxisSel;

// 列/行を丸ごと選択する（該当セルの id を selectedElementIds へ置換）＋ 軸選択を記録
export function selectTableAxis(
  api: any, tid: string, kind: "col" | "row", indices: number[],
  mode: "replace" | "extend" | "toggle",
): void;

// 一括リサイズの対象 index を解決（§3.2 の優先順ルール）
export function resolveSizeTargets(api: any, tid: string, kind: "col" | "row", index: number): number[];

// 複数の列/行へ手動サイズを一括適用。value<=0 でクリア（自動フィット復帰）
// ＝ 既存 TableResizeOverlay 内の applyManual を「複数 index 対応」にしてここへ移設
export function applyTableSizes(api: any, tid: string, kind: "col" | "row", indices: number[], value: number): void;

// 「そろえる」（列＝平均で均等割り / 行＝最大値に統一）
export function distributeTableSizes(api: any, tid: string, kind: "col" | "row", indices: number[]): boolean;
```

既存関数への変更:

- `selectedTableRange(...)`: 軸選択があればそれを優先して `rows`/`cols` に反映し `single: false` を返す。
  これで「1 列だけの表でヘッダーから列を選ぶ＝全セル選択」という**全体選択と見分けがつかないケースも
  正しく列選択として扱える**（現状は `selCount >= total` でフォーカスセル単体へフォールバックしてしまう）。
- `insertTableColumns` / `insertTableRows` / `deleteTableColumns` / `deleteTableRows`: 保持中の軸選択
  `indices` を同じ規則でシフト/除去する（1〜2 行）。これをしないと「3 列選択 → 左に追加」で軸選択が
  勝手に外れる。

### 4.2 `TableResizeOverlay.tsx`

- `readLayout()` に軸選択（`tableAxisSel`）を含める。
- `onDown`: `resolveSizeTargets` で `targets` を決め、`k`（ドラッグ index 以下の対象数）と各対象の基準サイズを
  ドラッグ状態に保持。
- `onMove`: §3.2 の式で `w` を求め、`applyTableSizes(tid, kind, targets, w)`。
- `onDbl`: `applyTableSizes(tid, kind, targets, 0)`。
- **ヘッダー帯つまみ（`head-col` / `head-row`）を追加**。既存の `buildHandles` に `C + R` 個追加し、
  `position()` で毎フレーム矩形を更新する（既存と同じ scene→ローカル画面 px 変換）。選択ハイライトは
  DOM 再構築ではなく `style.background` の書き換えのみで行う（**React 再レンダーを挟まない＝ちらつかない**、
  既存オーバーレイの方針を踏襲）。ドラッグ中は一緒に動く境界つまみも ACCENT で光らせる。
- 帯のドラッグ範囲選択は `axisIndexAt`（画面座標 → `viewportCoordsToSceneCoords` → 累積サイズで index）。
- `structRef` の署名 `tid:C:R` は据え置き（帯の個数も C/R に従うため）。帯ドラッグ中は作り直さない。

### 4.3 `TableRowColControls.tsx`

- §3.4 の「サイズ」セクションを追加。
- 毎フレームの `sig` 比較で `setState` を抑制している既存構造を維持し、**sig に「サイズ行を出すか」
  （＝対象列数・行数）も含める**。含め忘れるとパネルが更新されない/毎フレーム再描画になる。
- パネル高さ `PANEL_H = 120` を実寸に合わせて更新（ドッキング位置の判定に使われている）。

### 4.4 `WhiteboardCanvas.tsx`

変更なしの見込み（両オーバーレイはすでにマウント済み）。

## 5. `reflowTables` との整合

- 一括適用も**書き込むのは `cw`/`rh` だけ**。位置・寸法は従来どおり `onChange` 駆動の `reflowTables` が
  タイルし直す（新しいレイアウト経路を増やさない）。
- 総幅・総高が変わるため、表は**原点 (0,0) セル固定のまま右下方向へ伸縮**する（既存の列幅ドラッグと同じ）。
- 列幅を内容より狭くすると折り返しが増えて行高が伸びる。これも既存どおり。
- 幅の一括適用中も `reflowTables` は毎 tick 走るが、`_reflowing` 再入ガードと EPS 収束は既存のまま効く。

## 6. 履歴（Undo）とリアルタイム同期

- **ドラッグ**: 既存どおり `beginHistoryGesture()` → 離したら `commitSceneToHistory(api)` で
  **1 ドラッグ = 1 undo ステップ**（BRU7-058 の方式）。対象が n 列でも 1 ステップ。
- **パネル操作 / ダブルクリック**: 1 クリック = 1 ステップ。`insertTableRows` と同様に
  `captureUpdate: CaptureUpdateAction.IMMEDIATELY` を付ける。
- **同期**: `ExcalidrawYjsBridge.syncFromExcalidraw` は `version` / `versionNonce` 比較で伝播する。
  パネル経由の一括書き込みは `insertTableRows` と同じく **`version` / `versionNonce` を明示的に上げる**
  （上げないと他クライアントに伝播しない可能性がある）。ドラッグ経路は既存 `applyManual` と同じ書き方に
  そろえ、挙動を現状から変えない。
- 軸選択（ヘッダー帯の選択状態）は**ローカル UI 状態**。Yjs へは載せない。

## 7. エッジケース・リスク

| # | 内容 | 対応 |
|---|---|---|
| 1 | Excalidraw が個別セル選択をグループ選択へ正規化してしまう可能性 | 単一セルを `selectedElementIds` に入れる方式は `TableRowColControls` で実績あり。複数セルでも同様の想定だが、実装時に検証し、必要なら `selectedGroupIds: {}` / `editingGroupId` を併せて指定する |
| 2 | 帯が表の外側に出るため、下の図形がクリックできなくなる | 表を選択している間だけ表示。帯は不透明で見えるので誤操作になりにくい。`pointer-events` は帯の区画だけ `auto` |
| 3 | ズームアウト時に列幅が帯の太さ未満になる | 帯は画面 px 固定。潰れた区画はクリックしづらいが許容（既存 `GRIP=8` と同じ制約） |
| 4 | 行高を一括で小さくしても、内容の高い行は縮まない | 仕様（`rh` は下限）。§3.4 のとおり「高さをそろえる」は**最大値に統一**することで“揃わない”状態を作らない。仕様として文言でも明示 |
| 5 | 行列の追加/削除で軸選択の index がずれる | §4.1 のとおり追加/削除側でシフト。破綻した場合も `tableAxisSel` の検証で自動クリア（安全側） |
| 6 | 四隅ドラッグ（表全体スケール）との競合 | 四隅つまみは従来どおり全列・全行対象。軸選択の有無に関係なく挙動を変えない |
| 7 | 表全体選択（1 クリック）時に一括が暴発する | §3.2 の対象決定ルールで**明示的に除外**。互換維持 |

## 9. テスト観点

- 3 列選択 → いずれかの境界をドラッグ → **3 列が同じ幅**になり、ドラッグした境界がカーソルに追従する
- 左端の列を含む選択で、右側の境界をドラッグしても境界が走らない（`dx / k` の検証）
- 2 行選択 → 行境界ドラッグ → 2 行が同じ高さ。内容が高い行は縮まない（仕様どおり）
- 選択中の境界をダブルクリック → 選択全体が自動フィットへ戻る
- **表全体を 1 クリック選択 → 境界ドラッグ → 1 列だけ変わる（既存挙動の非破壊）**
- 一括ドラッグ後の Undo が **1 回で元に戻る**／Redo で戻る
- 2 クライアントで開き、一括リサイズが相手画面へ反映される
- ヘッダーから列を選択 → 「右に 3 列追加」→ 軸選択が保たれる／表示ラベルが「3 列」のまま
- 1 列だけの表・1 行だけの表で列/行選択が正しく効く
- セル内テキスト編集中に帯・つまみが暴れない（`busy` 判定の踏襲）
- ズーム/スクロール中に帯の位置がずれない
- 画像や他図形の上に表を置いても帯がクリックを奪いすぎない

## 10. スコープ外 / 拡張候補

- **数値でのサイズ指定**（パネルに `幅 [120] px` 入力）: 実装は容易だが本チケットの要件は選択＋一括調整なので
  Phase 5 の任意拡張とする。
- **セル結合**: 表モデルが `r/c` の単純格子である前提を崩すため対象外。
- **行高の手動値を「上書き」へ変更**（内容より低くできるようにする）: 見切れを生むため、別チケットで要検討。
- リッチテキストエディタ（TipTap）の表・Excel エディタの表は**本チケットの対象外**。
