# ENHA2-003 子チケットマージ機能 — 設計・実装方針

## 0. チケット概要

> 親チケットを１つ作って、そこに別の親を子供としてマージ追加できるようにする

既存の「子チケット作成」は**新規に空のチケットを生やす**ことしかできない。
本チケットでは、**既に存在する親チケットを、別の親チケットの子として取り込む（マージ）**操作を追加する。

---

## 1. 用語

| 用語 | 意味 |
|---|---|
| ターゲット (A) | 取り込み**先**の親チケット。マージ後も親のまま |
| ソース (B) | 取り込ま**れる**側の親チケット。マージ後は A の子になる |
| マージ | B を A の子にする操作 |
| デタッチ（切り離し） | マージの逆。子を独立した親チケットへ戻す |

---

## 2. データモデル

### 2.1 既存構造

```sql
-- supabase/add_child_tickets.sql
ALTER TABLE sprint_tickets
  ADD COLUMN IF NOT EXISTS parent_id TEXT REFERENCES sprint_tickets(id) ON DELETE CASCADE;
```

- `parent_id IS NULL` → 親チケット、`NOT NULL` → 子チケット
- **1階層のみ**（孫は非対応）。コード各所がこの前提に依存している
  - `SprintDetailPage.tsx:593` — `filter(t => !t.parentId)` で親だけリスト表示
  - `bulkTicketOps.ts` — `parent_id ?? id` でルートを解決
  - `parseSprintSegment()` — WBS 正規表現が `{sprint}-{3桁}-{枝番}` の2段まで
- WBS 採番規約
  - 親: `BRU10-083`（プレフィックス + ゼロ埋め3桁）
  - 子: `BRU10-083-1`（ゼロ埋めなしの枝番）

**結論: DBスキーマの変更は不要。`parent_id` と `wbs` の付け替えだけで実現できる。**

### 2.2 「孫が発生する」問題 → フラット化で解く

ソース B が既に子を持っている場合、素直に `B.parent_id = A.id` とすると B の子が孫になり、1階層前提が壊れる。

**採用方針: フラット化（B の子も A の直下へ引き上げる）**

```
【マージ前】                          【マージ後】
A  BRU10-001  認証基盤の刷新           A  BRU10-001  認証基盤の刷新
└─ A1 BRU10-001-1 ログイン画面         ├─ A1 BRU10-001-1 ログイン画面
                                       ├─ B  BRU10-001-2 SSO対応     ← 旧 BRU10-005
B  BRU10-005  SSO対応                  ├─ B1 BRU10-001-3 IdP連携     ← 旧 BRU10-005-1
├─ B1 BRU10-005-1 IdP連携              └─ B2 BRU10-001-4 SAML検証    ← 旧 BRU10-005-2
└─ B2 BRU10-005-2 SAML検証
```

- B の配下構造（B1/B2 が B にぶら下がっていた事実）は失われる
- これはダイアログで**明示して同意を取る**（後述のUI）
- 代替案「子を持つ親はマージ不可」も検討したが、実運用で最も畳みたいのは中身のある親なので却下
- 将来 `depth` 導入で多階層化するときは、この引き上げをやめるだけで移行できる

### 2.3 更新対象

| 対象 | 変更内容 |
|---|---|
| B 本体 | `parent_id = A.id` / `wbs = {A.wbs}-{n}` / `sprint_id = A.sprint_id` |
| B の子 | `parent_id = A.id` / `wbs = {A.wbs}-{n+1..}` / `sprint_id = A.sprint_id` |
| `ticket_comments` | **変更不要**（`ticket_id` 参照） |
| `ticket_source_files` | **変更不要**（`ticket_id` 参照） |
| `ticket_required_skills` | **変更不要**（`ticket_id` 参照） |
| `notifications.ticket_wbs` | 追わない（表示用スナップショット。`ticket_id` があるので遷移は生きる） |
| `action_memos.ticket_wbs` | 同上 |
| `backlog_items.converted_ticket_wbs` | 同上 |

`n` は「A 配下の既存子の枝番の最大値 + 1」。
`NewTicketDialog.tsx:477` と同じ注意点あり — **枝番はゼロ埋めしていないので DB の文字列ソートは使えない**。全件取得して数値比較で最大値を取ること（BRU4-058 と同じ罠）。

### 2.4 WBS が変わることの副作用（既知の割り切り）

WBS を振り直すため、以下は**リンク切れになる**。

1. リッチテキスト内の `#WBS` メンション（`RichEditor.tsx:767` — `data-id` に **WBS文字列**を保持している）
2. 共有済みの URL `/{projectSlug}/{旧WBS}`

これは**既存のスプリント移動（`bulkMoveTickets`）と全く同じ挙動**であり、
`MoveToSprintDialog.tsx:50` でも「移動先で採番（WBS）は振り直されます」と注意書きだけで済ませている。
本機能も**前例踏襲**とし、ダイアログに同じ注意書きを出す。

> 将来的に直すなら `ticket_wbs_aliases(old_wbs, ticket_id)` を作って
> `parseSprintSegment()` / `TicketShortUrlPage` で解決する別チケットに切る。ENHA2-003 のスコープ外。

## 3. バリデーション

`ticketMerge.ts` の `validateMerge()` に集約する。

### 3.1 ブロック（マージ不可）

| # | 条件 | メッセージ |
|---|---|---|
| 1 | ソース == ターゲット | 「同じチケットにはマージできません」 |
| 2 | ターゲットが子チケット（`parent_id != null`） | 「子チケットに他のチケットを取り込むことはできません」 |
| 3 | ターゲットがソースの子 | 「取り込み先が取り込み元の子チケットです（循環）」 |
| 4 | 別プロジェクト間 | 「同じプロジェクト内のチケットのみ取り込めます」 |
| 5 | `plan.featureChildTickets === false` | `PlanTooltip` で「現在のプランではご利用できません」 |
| 6 | `canEdit === false` | ボタン自体を出さない |

※ ソースが既に A の子 → 何もせず成功扱い（冪等）。

### 3.2 警告（続行可）

**A が完了系ステータスなのに、取り込む側が未完**のケース。

現行 `validateParentStatusChange()`（`helpers.ts:319`）は「未完の子があると親を完了にできない」を保証しているが、
マージはこの検査を**迂回できてしまう**（完了済み親に未完の子を後付けできる）。

→ ダイアログに警告 + **「親チケットのステータスを『進行中』に戻す」チェックボックス（デフォルト ON）** を置く。

```
STATUS_RANK による判定:
  A.status ∈ {in-review, stg-test, uat, done, closed} かつ
  取り込む全チケット（progress !== -2 の分）のいずれかが
  PARENT_STATUS_MIN_CHILD_RANK[A.status] 未満
    → 警告 + 巻き戻しチェックボックスを表示
```

`STATUS_RANK` / `PARENT_STATUS_MIN_CHILD_RANK` は `helpers.ts` の既存定数をそのまま再利用する。

### 3.3 ステータス値の変換は不要

子チケット固有のステータス体系は存在せず、`getTicketStatusMeta()`（`helpers.ts:60`）が
`closed` / `progress === -1,-2` を吸収するため、**B のステータスはそのまま維持**してよい。

## 5. 実装方針

### 5.1 原子性 — Postgres RPC を1本立てる

クライアント側で複数 UPDATE を流す実装（`bulkMoveTickets` 方式）だと、
途中で失敗したときに「B の子だけ A に移り、B は A の外に残る」= **孫でも兄弟でもない壊れた状態**が生まれうる。
マージは付け替えと採番が不可分なので、**RPC でトランザクションに包む**のが正しい。

```
supabase/add_ticket_merge.sql   (新規・1ファイル)

  create or replace function merge_tickets_into_parent(
    p_target_id  text,
    p_source_ids text[]
  ) returns table(ticket_id text, old_wbs text, new_wbs text)
  language plpgsql security invoker as $$
  ...
  $$;

  create or replace function detach_ticket_from_parent(
    p_ticket_id text
  ) returns table(ticket_id text, old_wbs text, new_wbs text)
  language plpgsql security invoker as $$
  ...
  $$;
```

RPC 内でやること:
1. ターゲットの行ロック（`select ... for update`）— 採番競合の防止
2. ターゲットが親であること、ソースがターゲット配下でないことを再検証（クライアント検証の二重化）
3. ターゲット配下の既存枝番の最大値を**数値として**取得（`substring` + `::int`、ゼロ埋め無し前提）
4. ソース → ソースの子 の順で `parent_id` / `wbs` / `sprint_id` を更新
5. 旧WBS→新WBS の対応表を返す（クライアントのプレビュー確定表示・ハイライトに使う）

`security invoker` にして既存 RLS をそのまま効かせる。

### 5.2 ファイル構成

| 種別 | パス | 内容 |
|---|---|---|
| 新規 | `supabase/add_ticket_merge.sql` | RPC 2本 |
| 新規 | `src/app/lib/ticketMerge.ts` | `validateMerge()` / `previewMerge()` / `mergeTicketsIntoParent()` / `detachTicketFromParent()` |
| 新規 | `src/app/components/tickets/MergeTicketDialog.tsx` | ピッカー（取り込み元 / 取り込み先の両モード）＋ 確認＋採番プレビュー |
| 改修 | `src/app/components/tickets/TicketDetailPanel.tsx` | 子チケットセクションのボタンをメニュー化（フロー①）／ 子チケットに「親から切り離す」（フロー③） |
| 改修 | `src/app/components/sprints/BulkActionBar.tsx` | 「親へマージ」ボタン追加 |
| 改修 | `src/app/components/sprints/useBulkTicketActions.tsx` | `bulkAction: "merge"` 分岐と実行ハンドラ |

`previewMerge()` はクライアント側の純関数として実装し、DBに触らず採番結果を計算する
（確認ダイアログの表示に使う）。実際の採番は RPC が真値を返すので、
**プレビューと結果がずれた場合は結果側を正**として完了トーストに出す。

### 5.3 プラン / 権限ゲート

既存の `plan.featureChildTickets`（`TicketDetailPanel.tsx:2883`）をそのまま流用する。
OFF のときは `PlanTooltip` でグレーアウト表示 — 「子チケット作成」と同じ扱い。
一括操作バー側も同様にゲートする。

### 5.4 監査コメント

`ticket_comments` に `comment_type: "status_change"` で流す
（新しい type を足すとレンダリング側の分岐漏れが出るため、既存のシステムコメント経路に乗せる）。
A 側・B 側の両方に1行ずつ残す。

### 5.5 リンクサジェストの同期

WBS が変わるので、他タブの `#` サジェストへ即時反映させる。
`emitLinkItemsChanged(projectId, "ticket")`（`linkSuggestSync.ts:69`）を完了後に呼ぶ。
`NewTicketDialog` / `bulkTicketInsert` と同じ扱い。

## 7. 検証観点

| # | ケース | 期待 |
|---|---|---|
| 1 | 子なしの親 → 別の親へマージ | 枝番が最大+1で採番される |
| 2 | 子2件を持つ親 → 別の親へマージ | 3件が連番でフラットに並ぶ |
| 3 | 子が10件以上ある親へマージ | 枝番が -11, -12… と続く（BRU4-058 の文字列ソート罠の再発チェック） |
| 4 | 別スプリントの親をマージ | 取り込み先のスプリントへ移動する |
| 5 | 一括で3件を1つの親へ | 選択順で連番、重複なし |
| 6 | 完了済み親へ未完チケットをマージ | 警告表示 + 親が「進行中」に戻る |
| 7 | 子チケットを取り込み先に指定 | ブロックされる |
| 8 | 取り込み元に取り込み先を含めて一括マージ | 当該行が選択不可になっている |
| 9 | マージ → 切り離し | 独立した親に戻り、親採番が振られる |
| 10 | 保留(-1) / 取下(-2) の子を含むマージ | ステータス警告の判定で取下は除外される |
| 11 | マージ後の親のステータス前進 | `validateParentStatusChange` が取り込んだ子も見る |
| 12 | プラン OFF | 導線がグレーアウトし `PlanTooltip` が出る |

## 8. 意図的にスコープ外にしたもの

- **旧WBSエイリアスによるリンク救済** — 既存のスプリント移動も同じ欠落があり、本機能単独で直すのは筋が違う。別チケット化を推奨
- **多階層（孫）対応** — `depth` カラム導入を伴う大改修。フラット化で回避
- **マージの取り消し（Undo）** — 切り離し（フロー③）で代替する。元の子構造の復元はしない
- **プロジェクトを跨いだマージ** — 採番プレフィックスとメンバー権限が絡むためブロックする
