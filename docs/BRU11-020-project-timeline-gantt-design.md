# BRU11-020 プロジェクト推移表示追加 — 設計書

## 0. 結論（サマリ）

プロジェクト一覧のカード3点メニューに **「プロジェクト推移」** を追加し、
**読み取り専用のガントチャートモーダル** を開く。

| # | 改修 | 規模 |
|---|------|------|
| A | `ProjectCard` に `onTimeline` prop とメニュー項目を追加 | 小 |
| B | `ProjectsPage` に開閉 state とモーダル描画を配線 | 小 |
| C | `ProjectTimelineModal`（新規）: モーダル枠・データ取得・サマリ帯 | 中 |
| D | `ProjectTimelineChart`（新規）: ガント描画本体（日/週/月の粒度切替） | 中 |

- **DBマイグレーション・型変更は不要。** 既存の `sprints` / `sprint_tickets` だけで描ける。
- **既存の `SprintGanttView` は一切触らない**（スプリント画面へのレグレッションを持ち込まない）。
- 新規2ファイル + 既存2ファイルの小改修。

## 1. 現状整理

### 1.1 3点メニューの現状

[ProjectCard.tsx:113-146](../src/app/components/projects/ProjectCard.tsx#L113-L146) に
`編集 / タグ編集 / 分類設定 / 設定 / CSVダウンロード / 削除` の6項目。
すべて「渡されたコールバックがあるときだけ出す」方式で、
[ProjectsPage.tsx:428-439](../src/app/pages/ProjectsPage.tsx#L428-L439) が権限に応じて渡している。
モーダルは `xxxTarget` state（`Project | null`）を立てて末尾で描く一貫したパターン。

### 1.2 すでにあるガント資産

[SprintGanttView.tsx](../src/app/components/sprints/SprintGanttView.tsx) がスプリント画面の
ガント表示を担っている。左ペイン固定240px＋右ペイン横スクロールという構造、
`getLeft()` / `getWidth()` によるバー配置、年/月/日の3段ヘッダ、今日ラインなど、
**描画方式はそのまま踏襲できる**。

### 1.3 なぜ `SprintGanttView` をそのまま再利用しないか

| 理由 | 詳細 |
|------|------|
| ① 固定5年レンジ | [SprintGanttView.tsx:121-125](../src/app/components/sprints/SprintGanttView.tsx#L121-L125) は今年〜+4年の1825日を常に描く（幅36,500px、グリッド線1825本＋日セル1825個）。モーダルの俯瞰用途には過剰 |
| ② 編集・遷移前提のprops | `onSelectSprint` / `onCreateTicket` / `onBulkCreate` は画面遷移や作成ダイアログを開く。モーダル内から呼ぶとモーダルを閉じる必要があり責務が混ざる |
| ③ localStorage キー衝突 | アコーディオン開閉を `sprint_accordion_states` に永続化している（:9, :59-76）。モーダルで開閉するとスプリント画面のガントの状態まで書き換わる |
| ④ 「推移」に必要な要素が無い | プロジェクト全体の集約バー、粒度切替（日/週/月）、期間の自動フィットが無い |

→ **表示ロジックは同型の実装を新コンポーネントに持たせる**。
共通化（軸計算の切り出し）は変更範囲が広がるため今回は行わず、将来の整理課題として残す。

### 2.3 行構成

| 段 | 行 | バーの期間 | 進捗 |
|----|----|-----------|------|
| 1 | **プロジェクト行**（常に先頭・1行） | `project.startDate` – `project.endDate` | チケット完了率（`calcProgress` と同基準） |
| 2 | **スプリント行** | `sprint.startDate` – `sprint.endDate` | `sprintProgress(sprint)` |
| 3 | **チケット行**（スプリント行を展開したときのみ） | `startDate` – `dueDate` | 既存ルールに準拠（下記2.5） |
| 4 | **子チケット行**（親チケット行を展開したときのみ） | 同上 | 同上 |

- 既定は**全スプリント折りたたみ**（「推移＝俯瞰」が目的のため）。
  `SprintGanttView` は既定展開だが、モーダルでは初見の情報量を抑える
- 開閉状態は**モーダルローカルの `useState` のみ**。localStorage には保存しない
  （スプリント画面のガントの開閉状態と干渉させないため。1.3-③）

### 2.4 時間軸

- **常に1年分（1/1〜12/31）を表示**し、ヘッダの `◀ 2026 ▶` で前後の年へ移動する。
  データ範囲にフィットさせる方式は「8月で終わって右側が空く」ため採らない
- 1年分がコンテナ幅に満たない場合（主に月粒度）は px/日 を引き伸ばして幅いっぱいに描き、
  はみ出す場合は横スクロールさせる（コンテナ幅は `ResizeObserver` で追随）
- 表示年から完全に外れた行は、バーの代わりに端へ `◀ 04/12 – 05/20` / `04/12 – 05/20 ▶` を出す
- 初回表示の年は今年。ただしプロジェクトのデータが今年を含まない場合は、
  データのある年（最も近い側）へ寄せてから開く
- **粒度切替**（1日あたりの px）
  | 粒度 | px/日 | ヘッダ段 |
  |------|------|---------|
  | 日 | 22 | 年 / 月 / 日 |
  | 週 | 6（=42px/週） | 年 / 月 / 週始日 |
  | 月 | 2 | 年 / 月 |
- 粒度は `localStorage: project_timeline_scale` に保存（次に開くとき同じ粒度）
- 今日ライン（緑2px）。初期スクロールで今日が左から1/3の位置に来るようにする。
  今日がレンジ外なら先頭（レンジより前）／末尾（レンジより後）へ寄せる
- ヘッダとボディの横スクロールは `onScroll` で同期（`SprintGanttView` と同方式）

### 2.5 バー仕様

- 色: スプリント = `getSprintStatusMeta(computeSprintStatus(s)).barColor` /
  チケット = `getTicketStatusMeta(t.status, t.progress).color`
  → **保留(-1)・取下(-2) のバッジ色も既存ヘルパー任せで自動的に正しくなる**
- 進捗フィル: 既存と同ルール
  `done / closed / waiting-release / released` は100%、`on-hold / withdrawn` は0%、それ以外は `t.progress`
- **実績バー（計画 vs 実績の2段表示）**: 完了しているもの（`done / closed / waiting-release / released`）は
  計画バーの下に細い実線バーで **着手日（`started_at`）〜クローズ日（`closed_at` → 無ければ `released_at`）** を描く。
  完了とみなす日時の優先順は ReportsPage と同じ。着手日が無いものは実績バーを出さない。
  スプリント行・プロジェクト行は配下チケットの「最早着手〜最終完了」を集約して描く
- **子チケットの完了日**: 子の「対応完了」はマイルストーンを記録していなかったため完了日が空だった。
  `handleChildComplete` で `released_at` だけを記録するよう変更する
  （`recordMilestoneFromTicketStatus` は呼ばない＝BRU9-042 の一括スタンプ問題は起こさない）。
  変更前に完了した子チケットは完了日が空のままなので、**親チケットの完了日で代替**して描く。
  代替した実績バーは点線＋薄色にし、日付ラベルに「（親）」を付けて確定値と区別する
- **遅延強調**: `dueDate < 今日` かつ未完了 → 赤の破線アウトライン。サマリ帯の「遅延」件数と一致させる
- 日程未設定: 「日程未設定」の薄字（既存表現を踏襲）
- ホバー情報: 初版は `title` 属性（名称／期間／進捗／担当／ステータス）。
  独自ツールチップは費用対効果が低いので入れない

## 3. データ取得

モーダルを開いたときに1回だけ取得する（カード一覧側の再取得は増やさない）。

```ts
// SprintPage.tsx:233 と同じ形。ネストも含めて .order() を必ず付ける
const { data } = await supabase!
  .from("sprints")
  .select("*, sprint_tickets(*)")
  .eq("project_id", project.id)
  .order("start_date")
  .order("id")
  .order("created_at", { referencedTable: "sprint_tickets" })
  .order("id",         { referencedTable: "sprint_tickets" });
const sprints = (data ?? []).map(mapSprint);
```

- **並び順はスプリント画面と揃える**: `fetchSprintOrder(project.id, userId)` →
  `applySprintOrder(sprints, order)`（[sprintOrder.ts](../src/app/lib/sprintOrder.ts)）。
  ユーザーが並び替えたスプリント順と推移表の行順が食い違わないようにする
- **`isSupabaseEnabled === false` のとき**: `data/mock.ts` の `SPRINTS` を `projectId` で絞って使う
  （既存のモック fallback 方針に合わせる）
- 集計（進捗・遅延件数・レンジ）はすべてクライアント側 `useMemo`。DBのVIEWや集計関数は追加しない

| ID | 症状 | 本設計での対策 |

## 5. パフォーマンス

- レンジをプロジェクト実期間に限定するため、日粒度でも通常は数百セル
  （`SprintGanttView` の固定1825日より軽い）
- 週/月粒度ではグリッド線・ヘッダセルを週単位／月単位に間引く（日単位ループを回さない）
- チケット行は展開時のみ描画。**仮想化は入れない**（想定行数は数十〜百数十）。
  1スプリント数百チケット規模が問題化したら別チケットで対応する

## 8. テスト観点

**表示**
- スプリント0件のプロジェクト → 空表示（プロジェクト行のみ ＋「スプリントがありません」）
- スプリント/チケットの日付が未設定 → 「日程未設定」表示、レンジ計算が壊れない
- 開始日 = 終了日（単日）のバーが潰れずに見える
- プロジェクト期間より外に出るスプリント／チケットがあってもレンジに含まれる
- 期限切れ未完了チケットが赤破線になり、サマリ帯の「遅延」件数と一致する
- 保留／取下チケットのバッジ色・進捗0%が既存画面と一致する
- 子チケットが親の展開で即座に出る（遅延しない）

**操作**
- 日/週/月の切替でバー位置がずれない。切替後もリロードで粒度が保持される
- 「今日へ」で今日ラインが見える位置にスクロールする
- 更新ボタンでチャートが消えない（BUG-02/03）
- Esc・オーバーレイクリックで閉じる。カードのメニューが閉じた状態に戻る
- 開閉を繰り返しても **スプリント画面ガントのアコーディオン状態が変わらない**

**権限・環境**
- 一般メンバー（`canManage=false`）でもメニューが出て開ける
- 他組織のプロジェクトが見えない（既存RLSのまま）
- `isSupabaseEnabled=false`（モック）でも開ける
- `npx vite build` が通る（型検証は本リポジトリのビルドゲート）

## 9. 仕様判断と確認したい点

### ① 「推移」の対象範囲 — **対象プロジェクト単体** と解釈した
メニューがカード単位に付くため、そのプロジェクトのスプリント／チケットの時間軸表示とした。
もし意図が「**全プロジェクトを横串で並べたガント**」であれば、導線はカードの3点メニューではなく
一覧画面のヘッダ（または新ページ）が適切で、設計が変わる。← **要確認**

### ② 進捗の時系列グラフ（バーンアップ）は今回スコープ外
「推移」を「時間による進捗の変化」と捉えるなら、累積作成 vs 累積完了の折れ線も候補になる。
`sprint_tickets` の `created_at` / `released_at` / `closed_at` から**再構成可能**なので、
必要なら本モーダルの上段に追加する第2段として実装できる。
チケット記載の期待値が「ガントチャートのようなもの」であることから、初版はガントに絞る。← **要確認**

### ③ 読み取り専用 — **編集導線は入れない**
バーのドラッグによる日程変更、チケット作成、詳細への遷移は入れない。
（遷移を入れるとモーダルを閉じてページ遷移する必要があり、一覧画面に戻れなくなるため）
必要なら「スプリント画面で開く」リンクをフッタに置く形で拡張できる。

### ④ プラン制限なし・権限制限なし（2.1 参照）

### ⑤ メニューの並び順は「設定」の下・「CSVダウンロード」の上（変更希望があれば調整）
